🎯 O que você vai construir

Você vai criar, do zero, o site de apresentação (a "landing page") de uma empresa SaaS — ou seja, uma empresa que vende um software por assinatura (pense em ferramentas como Spotify, Netflix, Canva: você não compra o programa, paga uma mensalidade para usar).

A empresa e o produto são inventados por você — pode ser um app de estudos, uma ferramenta de organização de tarefas, um editor de imagens, o que você quiser.

🎨 Tema totalmente livre

Escolha a ideia do produto, o nome da empresa, as cores e o estilo visual. As imagens você mesmo vai buscar (bancos de imagem gratuitos, como Unsplash ou Pexels, ou ícones de sites como Flaticon) — este é um exercício de montar um site real, então a pesquisa de material faz parte do processo.

📂 Planejamento de pastas

Antes de codar, organize os arquivos. Para este projeto, mantenha simples — no máximo 3 páginas HTML:

estrutura simples (recomendada) meu-site-saas/ ├── index.html # sua página principal — obrigatória ├── style.css # todo o CSS num arquivo só ├── script.js # todo o JavaScript num arquivo só └── imagens/ ├── logo.png ├── icone-1.svg └── foto-hero.jpg

Tudo cabe numa index.html só, com seções (hero, recursos, preços...) uma embaixo da outra — é o jeito mais simples de começar, e totalmente válido para esta atividade.

Se preferir separar em mais de uma página, pode — só não passe de 3 páginas HTML no total:

variação com 3 páginas meu-site-saas/ ├── index.html # página inicial (hero + recursos) ├── precos.html # página de planos ├── contato.html # página de contato ├── style.css # o mesmo CSS vale para as 3 páginas ├── script.js └── imagens/
Por que um style.css e um script.js só, mesmo com várias páginas? Cada página HTML linka os dois mesmos arquivos (<link rel="stylesheet" href="style.css"> e <script src="script.js"></script>) — assim você escreve um estilo uma vez só e ele vale pro site inteiro, sem repetir código.

🧩 Seções do site

Um site SaaS costuma ter: cabeçalho, um destaque inicial (hero), recursos do produto, planos e preços, e contato/rodapé. A ordem, as cores, os espaçamentos e quantos itens cada seção tem são decisão sua — abaixo tem um exemplo de código pra cada parte, pra você usar como ponto de partida e modificar à vontade.

Estrutura base da página

index.html<!DOCTYPE html> <html lang="pt-BR"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>NomeDoSeuProduto</title> <link rel="stylesheet" href="style.css"> </head> <body> <header>...</header> <section id="inicio">...</section> <section id="recursos">...</section> <section id="precos">...</section> <footer id="contato">...</footer> <script src="script.js"></script> </body> </html>

O <nav>, o conteúdo do hero, etc. entram dentro de cada tag — o esqueleto acima é só o ponto de partida. Agora vamos seção por seção: cada bloco abaixo traz o HTML e o CSS completo, pronto pra você copiar, colar e modificar.

Modelo — Cabeçalho com navegação

O <header> fica no topo de todas as páginas. Dentro dele, um <nav> alinha o logo à esquerda e os links à direita, usando Flexbox.

Modelo · adapte cores, links e logo
html<header> <nav class="navbar"> <a href="index.html" class="logo">SeuProduto</a> <ul class="menu"> <li><a href="#inicio">Início</a></li> <li><a href="#recursos">Recursos</a></li> <li><a href="#precos">Preços</a></li> <li><a href="#contato">Contato</a></li> </ul> <button class="botao-menu">☰</button> </nav> </header>
style.css/* ── Cabeçalho ── */ header { background: #fff; box-shadow: 0 2px 8px rgba(0,0,0,0.08); position: sticky; /* gruda no topo ao rolar */ top: 0; z-index: 100; } .navbar { display: flex; align-items: center; justify-content: space-between; padding: 16px 40px; max-width: 1200px; margin: 0 auto; } .logo { font-size: 1.5em; font-weight: 800; color: #7c3aed; /* troque pela cor do seu produto */ text-decoration: none; } .menu { display: flex; list-style: none; gap: 28px; } .menu a { text-decoration: none; color: #333; font-weight: 500; transition: color 0.2s; } .menu a:hover { color: #7c3aed; } /* O botão ☰ começa escondido — só aparece no celular */ .botao-menu { display: none; background: none; border: none; font-size: 1.6em; cursor: pointer; }

O position: sticky faz o cabeçalho grudar no topo quando o usuário rola — isso é bem comum em sites SaaS. Se preferir que ele não grude, é só remover as linhas position, top e z-index.

Modelo — Seção Hero (destaque inicial)

O hero é o primeiro bloco que o visitante vê — geralmente uma frase de impacto, um subtítulo e um botão chamativo. Aqui usamos background: linear-gradient(...) para criar um fundo degradê sem precisar de imagem.

Modelo · mude textos, cores e fundo
html<section id="inicio" class="hero"> <div class="hero-conteudo"> <h1>Organize sua vida com o <span>SeuProduto</span></h1> <p>A ferramenta que simplifica o que parece complicado.</p> <a href="#precos" class="botao-cta">Comece grátis</a> </div> </section>
style.css/* ── Hero ── */ .hero { background: linear-gradient(135deg, #7c3aed 0%, #4c1d95 100%); color: #fff; padding: 100px 40px; text-align: center; } .hero-conteudo { max-width: 700px; margin: 0 auto; } .hero h1 { font-size: 2.8em; margin-bottom: 18px; line-height: 1.2; } /* Destaque no nome do produto */ .hero h1 span { color: #a78bfa; } .hero p { font-size: 1.2em; opacity: 0.9; margin-bottom: 30px; } /* Botão de ação (CTA = Call To Action) */ .botao-cta { display: inline-block; background: #fff; color: #4c1d95; padding: 14px 36px; border-radius: 8px; font-size: 1.1em; font-weight: 700; text-decoration: none; transition: transform 0.2s, box-shadow 0.2s; } .botao-cta:hover { transform: translateY(-3px); box-shadow: 0 8px 20px rgba(0,0,0,0.25); }

O linear-gradient mistura duas cores — troque pelos tons do seu produto. Se preferir uma imagem de fundo em vez do degradê, use background: url('imagens/foto-hero.jpg') center/cover; no lugar.

Modelo — Cards de recursos (com grid em Flex)

A seção de recursos mostra o que o produto faz. Cada recurso fica dentro de um "card" — e os cards ficam lado a lado usando Flexbox com flex-wrap, que automaticamente quebra a linha quando não cabe mais.

Modelo · duplique o card quantas vezes quiser
html<section id="recursos" class="secao-recursos"> <h2>O que o SeuProduto faz por você</h2> <div class="grade-recursos"> <!-- Copie este card quantas vezes quiser --> <div class="card-recurso"> <img src="imagens/icone-1.svg" alt=""> <h3>Nome do recurso</h3> <p>Uma frase curta explicando o que esse recurso faz.</p> </div> </div> </section>
style.css/* ── Seção de recursos ── */ .secao-recursos { padding: 80px 40px; text-align: center; } .secao-recursos h2 { font-size: 2em; margin-bottom: 40px; color: #1a1a2e; } /* O container flexível: itens lado a lado, quebrando linha automaticamente quando não cabem mais */ .grade-recursos { display: flex; flex-wrap: wrap; gap: 24px; justify-content: center; max-width: 1100px; margin: 0 auto; } .card-recurso { background: #fff; border-radius: 12px; padding: 30px 24px; box-shadow: 0 4px 15px rgba(0,0,0,0.08); flex: 1 1 280px; /* cresce, encolhe, base de 280px */ max-width: 340px; /* não fica largo demais */ text-align: center; transition: transform 0.2s, box-shadow 0.2s; } .card-recurso:hover { transform: translateY(-6px); box-shadow: 0 12px 30px rgba(0,0,0,0.12); } .card-recurso img { width: 48px; height: 48px; margin-bottom: 16px; } .card-recurso h3 { font-size: 1.15em; color: #1a1a2e; margin-bottom: 8px; } .card-recurso p { color: #666; font-size: 0.95em; }

O segredo é flex: 1 1 280px — cada card tenta ter pelo menos 280px, mas cresce pra preencher o espaço. Com 3 cards, ficam lado a lado; com 6, ficam em duas linhas; no celular, cada um ocupa a tela inteira. Copie o <div class="card-recurso"> quantas vezes quiser — 2, 5, 8, o número é seu.

Modelo — Formulário de contato

Um formulário simples de contato, com os campos estilizados. Ele não vai enviar dados de verdade (isso precisa de back-end), mas serve para praticar HTML de formulário e CSS de inputs — e mais adiante a gente faz a validação com JavaScript.

🎨 CSS — Estilos globais e reset

No começo do style.css, coloque um reset e as configurações gerais do site. Isso garante que todos os navegadores exibam igual e define a fonte, as cores e o comportamento de rolagem do site inteiro.

style.css (começo do arquivo)/* ── Reset e base ── Tira margens e paddings padrão de todos os elementos e faz box-sizing funcionar de forma intuitiva. */ * { margin: 0; padding: 0; box-sizing: border-box; } html { scroll-behavior: smooth; /* rolagem suave ao clicar nos links #ancora */ } body { font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif; color: #333; line-height: 1.6; background: #fff; } img { max-width: 100%; /* imagens nunca furam o container */ display: block; } a { color: #7c3aed; } h1, h2, h3 { line-height: 1.2; }
O que é box-sizing: border-box? Sem ele, padding e border são somados à largura — um elemento com width: 100% e padding: 20px ficaria maior que 100%. Com border-box, tudo conta dentro dos 100%. Sempre use no reset.

🎨 CSS — Botões, cores e efeitos hover

Efeitos visuais fazem o site parecer profissional. A propriedade transition cria animações suaves entre estados (normal → hover, por exemplo), e transform move/escala o elemento sem mexer no layout.

Transition — o segredo dos efeitos suaves

Quando você define transition, qualquer mudança naquela propriedade acontece suavemente, em vez de trocar de repente:

style.css/* Sem transition: ao passar o mouse, a cor muda instantaneamente. Com transition: a cor muda em 0.3 segundos, suavemente. */ .botao { background: #7c3aed; color: #fff; padding: 12px 28px; border: none; border-radius: 8px; cursor: pointer; font-size: 1em; font-weight: 600; /* Quais propriedades animar e por quanto tempo */ transition: background 0.3s, transform 0.2s, box-shadow 0.2s; } .botao:hover { background: #6d28d9; /* cor mais escura */ transform: translateY(-2px); /* sobe 2px */ box-shadow: 0 6px 16px rgba(0,0,0,0.15); }

Variações de botão

Um site normalmente tem mais de um estilo de botão — por exemplo, um primário (preenchido) e um secundário (só contorno):

style.css/* Botão secundário — fundo transparente, só a borda */ .botao-secundario { background: transparent; color: #7c3aed; border: 2px solid #7c3aed; padding: 12px 28px; border-radius: 8px; cursor: pointer; font-weight: 600; transition: background 0.2s, color 0.2s; } .botao-secundario:hover { background: #7c3aed; color: #fff; }

Efeitos em cards (hover + sombra)

Cards que "levantam" ao passar o mouse dão sensação de interatividade. Basta combinar transform com box-shadow:

style.css.card { background: #fff; border-radius: 12px; padding: 24px; box-shadow: 0 2px 8px rgba(0,0,0,0.06); transition: transform 0.25s, box-shadow 0.25s; } .card:hover { transform: translateY(-8px); box-shadow: 0 16px 40px rgba(0,0,0,0.12); }

📱 CSS — Tornando responsivo com @media

O site precisa funcionar bem no computador e no celular. Para isso, usamos @media queries — blocos de CSS que só valem quando a tela tem um certo tamanho. Coloque estes blocos no final do style.css, depois de todos os outros estilos.

Regra de ouro: no CSS principal (sem @media), escreva o layout para tela grande. Depois, nos @media, ajuste o que precisa mudar para telas menores. Essa abordagem se chama "desktop first".
style.css (final do arquivo)/* ════════════════════════════════════════════════ TABLET — telas de até 900px ════════════════════════════════════════════════ */ @media (max-width: 900px) { /* Navbar empilha: logo em cima, menu embaixo */ .navbar { flex-direction: column; gap: 12px; } /* Hero com menos espaço */ .hero { padding: 60px 24px; } .hero h1 { font-size: 2em; } /* Cards: 2 por linha em vez de 3 */ .card-recurso { flex: 1 1 45%; max-width: none; } /* Planos empilham verticalmente */ .plano.destaque { transform: none; /* tira o scale(1.05) */ } } /* ════════════════════════════════════════════════ CELULAR — telas de até 600px ════════════════════════════════════════════════ */ @media (max-width: 600px) { /* Menu escondido por padrão — aparece quando o JS adiciona a classe "aberto" */ .menu { display: none; flex-direction: column; gap: 0; width: 100%; text-align: center; } .menu.aberto { display: flex; } .menu a { padding: 12px 0; border-bottom: 1px solid #eee; } /* Mostra o botão ☰ */ .botao-menu { display: block; } /* Hero mais compacto */ .hero { padding: 50px 20px; } .hero h1 { font-size: 1.6em; } /* Cards: 1 por linha */ .card-recurso { flex: 1 1 100%; } /* Seções com menos padding lateral */ .secao-recursos, .secao-precos, .secao-contato { padding: 50px 20px; } /* Rodapé empilhado */ .rodape-conteudo { flex-direction: column; text-align: center; } }

Como testar no celular sem ter celular?

No navegador (Chrome, Edge, Firefox), aperte F12 para abrir as Ferramentas do Desenvolvedor. Clique no ícone de celular/tablet no canto superior — isso simula a tela de diferentes dispositivos. Arraste a largura para ver seu site se adaptar.

⚡ JavaScript — Interatividade

A atividade pede pelo menos uma interação real em JavaScript. Abaixo tem quatro exemplos prontos — escolha uma ou mais, ou invente a sua. Tudo vai no script.js.

JS 1 — Menu mobile (abre/fecha)

O botão ☰ que você colocou no <header> precisa de JavaScript para funcionar. Ao clicar, ele adiciona/remove a classe aberto no menu — e o CSS que você escreveu no @media (max-width: 600px) cuida do resto:

script.js// ── Menu mobile ── const botaoMenu = document.querySelector('.botao-menu'); const menu = document.querySelector('.menu'); botaoMenu.addEventListener('click', () => { menu.classList.toggle('aberto'); }); // Fecha o menu quando um link é clicado menu.querySelectorAll('a').forEach(link => { link.addEventListener('click', () => { menu.classList.remove('aberto'); }); });

O classList.toggle funciona assim: se a classe aberto existe, ele tira; se não existe, ele coloca. É um interruptor.

JS 2 — Scroll suave ao clicar nos links

Se você já colocou scroll-behavior: smooth no CSS, o scroll suave já funciona para links com #ancora. Mas se quiser controlar pelo JavaScript (por exemplo, para fechar o menu mobile ao mesmo tempo), use isto:

script.js// ── Scroll suave nos links de navegação ── document.querySelectorAll('a[href^="#"]').forEach(link => { link.addEventListener('click', (e) => { const destino = document.querySelector(link.getAttribute('href')); if (destino) { e.preventDefault(); destino.scrollIntoView({ behavior: 'smooth' }); } }); });

O querySelectorAll('a[href^="#"]') pega todos os links que começam com # — ou seja, links internos da página. Ao clicar, rola suavemente até o elemento com aquele id.

JS 3 — Botão "Voltar ao topo"

Um botão flutuante que aparece quando o usuário rola para baixo, e leva de volta ao topo ao clicar:

html (antes de fechar o </body>)<button class="btn-topo" id="btn-topo">↑</button>
style.css.btn-topo { position: fixed; /* fica fixo na tela, não rola junto */ bottom: 30px; right: 30px; background: #7c3aed; color: #fff; border: none; width: 48px; height: 48px; border-radius: 50%; font-size: 1.4em; cursor: pointer; opacity: 0; /* começa invisível */ transition: opacity 0.3s; pointer-events: none; /* não clicável enquanto invisível */ } .btn-topo.visivel { opacity: 1; pointer-events: auto; }
script.js// ── Botão voltar ao topo ── const btnTopo = document.getElementById('btn-topo'); window.addEventListener('scroll', () => { if (window.scrollY > 400) { btnTopo.classList.add('visivel'); } else { btnTopo.classList.remove('visivel'); } }); btnTopo.addEventListener('click', () => { window.scrollTo({ top: 0, behavior: 'smooth' }); });

O window.scrollY retorna quantos pixels a página já rolou. Se rolou mais de 400px, mostra o botão; se rolou menos, esconde. O position: fixed no CSS garante que ele fica no canto da tela mesmo enquanto rola.

JS 4 — Validação do formulário de contato

Quando o usuário clicar em "Enviar", conferimos se os campos foram preenchidos corretamente antes de "enviar" (neste caso, mostrar uma mensagem de sucesso):

script.js// ── Validação do formulário ── const form = document.getElementById('form-contato'); form.addEventListener('submit', (e) => { e.preventDefault(); // impede o envio real (não temos back-end) const nome = document.getElementById('nome').value.trim(); const email = document.getElementById('email').value.trim(); const mensagem = document.getElementById('mensagem').value.trim(); // Verifica se algum campo ficou vazio if (!nome || !email || !mensagem) { alert('Por favor, preencha todos os campos.'); return; } // Verifica se o e-mail tem formato válido if (!email.includes('@') || !email.includes('.')) { alert('Por favor, insira um e-mail válido.'); return; } // Tudo certo — mostra mensagem de sucesso alert('Mensagem enviada com sucesso! (simulação)'); form.reset(); // limpa os campos });

O e.preventDefault() impede o formulário de recarregar a página. O .trim() remove espaços em branco no início e fim do texto — sem ele, alguém que digitasse só espaços passaria na validação. O form.reset() limpa todos os campos do formulário.

Não precisa usar estes quatro. A atividade pede pelo menos uma interação. Escolha a(s) que fizerem sentido pro seu site, ou invente as suas — um contador animado, uma galeria de imagens, um FAQ que abre/fecha, o que quiser. O importante é que seja algo funcional, não só decoração.

💡 Dicas extras de CSS

Centralizar qualquer coisa com Flexbox

Se precisar centralizar algo (horizontal e verticalmente), use:

style.css.centralizado { display: flex; justify-content: center; /* centraliza no eixo horizontal */ align-items: center; /* centraliza no eixo vertical */ }

Espaçamento com gap (em vez de margin)

Dentro de um container flex, use gap em vez de margin nos filhos — é mais limpo:

style.css/* Em vez de dar margin-right em cada card... */ .container-cards { display: flex; gap: 24px; /* espaço entre os itens, sem margin */ }

Limitar a largura do conteúdo sem perder o fundo

Quando uma seção tem fundo colorido de ponta a ponta, mas o texto precisa ficar centralizado e limitado:

style.css/* A section ocupa toda a largura (fundo colorido). O conteúdo dentro fica limitado a 1100px e centralizado. */ .secao { background: #f8f5ff; padding: 80px 40px; } .secao .conteudo { max-width: 1100px; margin: 0 auto; /* auto nas laterais = centralizado */ }

Sombra de texto para legibilidade em imagens

Se colocar texto sobre uma imagem de fundo, uma sombra sutil ajuda a ler:

style.css.hero-com-foto { background: url('imagens/foto-hero.jpg') center/cover; color: #fff; } .hero-com-foto h1 { text-shadow: 0 2px 10px rgba(0,0,0,0.5); }

⚙️ Requisitos técnicos

A criatividade é livre — mas estes pontos valem para qualquer versão do seu site:

  • HTML semântico — use as tags certas para cada parte (<header>, <section>, <footer>, <nav>), não tudo em <div>;
  • CSS todo seu — sem frameworks prontos tipo Bootstrap; o objetivo é praticar CSS de verdade;
  • Responsivo — o site precisa funcionar bem tanto no computador quanto no celular (use @media);
  • Pelo menos 1 interação em JavaScript — menu mobile, validação de formulário, efeito de scroll, etc.;
  • Imagens leves — comprima as imagens antes de usar, para o site carregar rápido.

📦 Entrega — como salvar seu progresso

Esta atividade não tem data de entrega marcada — ela é grande de propósito, para você desenvolver com calma ao longo de várias aulas. A forma de "entregar" é simples:

Sempre que terminar uma parte (uma seção, um efeito, uma correção), faça um commit descrevendo o que fez, e dê git push. Não sabe como? Veja o guia Git e GitHub — Criando seu Repositório antes de começar.

Sugestão de commits ao longo do projeto

Não espere o site ficar pronto para commitar. Cada etapa merece um commit separado:

terminal# Primeiro commit — só a estrutura HTML git add . git commit -m "Criar estrutura HTML com header, hero e sections" git push # Segundo commit — CSS do cabeçalho e hero git add . git commit -m "Estilizar header com navbar sticky e hero com gradiente" git push # Terceiro commit — seção de recursos git add . git commit -m "Adicionar cards de recursos com hover e flex grid" git push # E assim por diante...

Seu instrutor vai acompanhar o histórico de commits do seu repositório no GitHub — múltiplos commits ao longo do tempo mostram seu processo de trabalho e sua evolução.

✅ Checklist antes de considerar concluído

  • Cabeçalho com navegação (logo + links), hero, recursos, preços e contato/rodapé estão presentes;
  • O CSS tem estilos para todas as seções: header, hero, cards, planos, formulário e rodapé;
  • Os botões e cards têm efeito hover com transition;
  • O site fica legível e utilizável tanto no celular quanto no computador (@media funcionando);
  • Existe pelo menos uma interação em JavaScript funcionando (menu mobile, validação, scroll, etc.);
  • As imagens usadas têm crédito/fonte anotado (mesmo que num comentário no HTML);
  • O repositório no GitHub tem vários commits, não só um único commit final;
  • Os arquivos estão organizados: index.html, style.css, script.js (e no máximo mais 2 páginas HTML, se dividiu).
