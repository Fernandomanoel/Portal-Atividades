🎯 O plano desta etapa

Duas coisas hoje: primeiro, resolver aquele problema do fim da Etapa 3 — o app esquecendo tudo quando fecha. Depois, a parte mais empolgante até agora: ver seu app rodando dentro de um celular Android simulado, direto no computador.

💾 Por que o array esquece tudo

🧊 Memória RAM x Geladeira

O array missoes que você criou na Etapa 3 vive na memória RAM do navegador — é como escrever numa lousa: rápido de usar, mas quando você desliga (fecha a aba), tudo apaga. O localStorage é diferente: é como guardar na geladeira — some da lousa, mas continua lá quando você volta, mesmo depois de fechar tudo e religar o computador.

O localStorage é uma "gaveta" de memória permanente que cada navegador (e cada app baseado em Cordova) reserva pra guardar dados pequenos, sem precisar de internet nem de um banco de dados de verdade.

🧩 Passo a passo: salvando e recuperando

⚠️ O localStorage só guarda texto (strings) — nunca um array ou objeto direto. Por isso vamos usar duas funções amigas: JSON.stringify() (transforma o array numa string pra guardar) e JSON.parse() (transforma a string de volta num array pra usar). Sempre que salvar, é stringify; sempre que ler, é parse.
  1. Carregar as missões salvas assim que o app abre. Troque a linha let missoes = []; por esta, lá no topo do www/js/index.js:
    www/js/index.jslet missoes = JSON.parse(localStorage.getItem('minhas_missoes')) || [];

    localStorage.getItem('minhas_missoes') busca o que estiver guardado com esse nome. Na primeira vez que o app roda, não existe nada salvo ainda — getItem devolve null, e o || [] (leia "ou") diz: "se vier vazio/nulo, comece com uma lista vazia em vez de quebrar".

  2. Salvar toda vez que a lista mudar. Dentro da função desenharLista() que você já tem, adicione uma linha no começo:
    www/js/index.jsfunction desenharLista() { localStorage.setItem('minhas_missoes', JSON.stringify(missoes)); // salva sempre listaNaTela.innerHTML = ""; missoes.forEach((missao, indice) => { listaNaTela.innerHTML += ` <ion-item> <ion-label>${missao}</ion-label> <ion-button slot="end" color="danger" fill="clear" onclick="excluirMissao(${indice})"> <ion-icon name="trash" slot="icon-only"></ion-icon> </ion-button> </ion-item> `; }); }

    Como desenharLista() já é chamada depois de adicionar e depois de excluir uma missão (você programou isso na Etapa 3), colocando o setItem logo no início dela, o app salva sozinho em toda mudança — sem precisar lembrar de salvar em cada lugar separado.

💾 Teste de verdade: adicione 2-3 missões, feche a aba do navegador completamente, abra de novo e rode cordova run browser. As missões devem continuar lá. Se sumiram, confira se o nome 'minhas_missoes' está escrito exatamente igual nos dois lugares (no getItem e no setItem) — é o erro mais comum aqui.

📱 Preparando o celular virtual (emulador Android)

Chegou a hora de ver o app rodando dentro de um Android simulado. Vamos usar o Android Studio, que já está instalado no computador.

  1. Abra o Android Studio.
  2. No menu, procure More Actions (ou o ícone de três pontinhos na tela inicial) e clique em Virtual Device Manager.
  3. Clique em Create Device.
  4. Escolha um modelo de celular da lista — o Pixel 2 é uma boa escolha, tamanho de tela comum. Clique em Next.
  5. Escolha uma imagem do sistema Android pra instalar no celular virtual (por exemplo, a versão Q (Android 10)). Se pedir pra baixar, clique em Download e espere terminar.
  6. Antes de finalizar, abra Show Advanced Settings e mude a quantidade de RAM do celular virtual para algo entre 1500 MB e 2000 MB — isso evita que o computador trave, já que o celular virtual "empresta" memória do PC de verdade.
  7. Clique em Finish. O celular virtual vai aparecer na lista do Virtual Device Manager.
  8. Clique no botão de Play (▶) ao lado dele para ligar o celular virtual. Isso pode demorar um pouco na primeira vez — é normal, é como ligar um celular de verdade pela primeira vez.

🚀 Rodando o app dentro do celular virtual

Com o celular virtual ligado e a tela inicial do Android visível, volte pro terminal, dentro da pasta meu-app, e rode:

terminalcordova platform add android cordova run android

O primeiro comando (só precisa rodar uma vez) ensina o Cordova a construir versões para Android. O segundo instala e abre o app dentro do celular virtual que está ligado — como se você tivesse instalado ele num celular de verdade. Se tudo deu certo, o ícone "Minhas Missões" aparece na tela do Android simulado, e ao abrir, seu app roda igualzinho ao que você viu no navegador — só que agora dentro de um celular.

🐢 Por que pode demorar?

A primeira vez que você roda cordova run android costuma ser mais lenta — o Cordova precisa "montar" o app inteiro do zero. Da segunda vez em diante fica bem mais rápido. Aproveite essa primeira espera pra uma pausa de 10 minutos.

🕵️ Modo detetive no emulador

Se o app não abrir ou aparecer uma tela em branco dentro do celular virtual, o Console de sempre (F12) não vai ajudar — ele só funciona pra páginas abertas no navegador do computador. No emulador, o jeito de investigar é diferente e mais avançado; por hoje, se algo der errado, os erros mais comuns são:

  • Esqueceu de rodar cordova platform add android antes do run;
  • O celular virtual não estava ligado quando você rodou cordova run android;
  • Algum erro de JavaScript que também apareceria no navegador — por isso, sempre teste primeiro com cordova run browser e só depois confirme no emulador.
