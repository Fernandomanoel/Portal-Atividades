📋 O cenário: a lojinha de eletrônicos

Uma loja de produtos eletrônicos decidiu organizar o estoque usando um banco de dados. Em vez de anotar tudo numa planilha solta, ela quer guardar cada produto numa tabela chamada produtos, com estas informações:

  • id — um número único que identifica o produto
  • nome — o nome do produto
  • preco — o preço de venda
  • quantidade — quantas unidades tem em estoque

Objetivo da atividade

Criar a tabela produtos, cadastrar 5 produtos reais da loja e praticar as consultas mais usadas no dia a dia: SELECT, WHERE, ORDER BY, UPDATE e DELETE.

1️⃣ Criando a tabela

Para criar a tabela usamos CREATE TABLE, indicando o nome de cada coluna e o tipo de dado que ela guarda:

SQL correto
CREATE TABLE produtos ( id INT PRIMARY KEY, nome VARCHAR(100), preco FLOAT, quantidade INT );

⚠️ Atenção: erros comuns (e por que eles acontecem)

Se você já viu uma versão desta atividade com erro, vale entender exatamente o que estava errado — porque são erros que todo mundo comete quando está aprendendo SQL.

ERRO 1 — vírgula faltando

Uma versão errada da tabela ficava assim:

CREATE TABLE produtos( id INT PRIMARY KEY, nome VARCHAR(100), preço FLOAT quantidade INT );

Repare que depois de preço FLOAT não tem vírgula antes de quantidade INT. No SQL, toda coluna dentro do CREATE TABLE precisa terminar com vírgula, exceto a última. Sem a vírgula, o banco de dados não sabe onde termina uma coluna e começa a próxima — e o comando dá erro de sintaxe.

ERRO 2 — nome de coluna com acento

A coluna estava escrita como preço, com cedilha. O problema é que nomes de coluna com acentos e caracteres especiais podem dar problema em vários bancos de dados (MySQL, SQLite e outros), principalmente se o servidor não estiver configurado para aceitar acentuação (charset UTF-8 correto). Isso pode gerar erro na hora de criar a tabela ou, pior, funcionar em um computador e dar erro em outro.

A solução mais segura é evitar acentos nos nomes de coluna: usamos preco em vez de preço. Se quiser mesmo manter o acento, é possível colocar o nome entre crases no MySQL (`preço`) ou aspas duplas em outros bancos, mas isso deixa toda consulta mais chata de escrever — por isso a prática recomendada é simplesmente não usar acento em nomes de tabela e coluna.

ERRO 3 — INSERT incompleto e com valor errado

Uma versão errada do cadastro do Mouse ficava assim:

INSERT INTO produtos(id, nome, preco, quantidade) VALUES (1, 'Mouse', 50, 'Quantidade'),

Dois problemas aqui: primeiro, no lugar da quantidade em estoque (que deveria ser o número 10), foi colocado o texto 'Quantidade' — ou seja, a palavra em vez do valor. Segundo, o comando termina com vírgula, como se fosse continuar com mais produtos, mas não continua — e sem um ; no final, o SQL fica esperando mais linhas e o comando nunca é considerado completo.

Toda vez que o INSERT tiver várias linhas, cada linha termina em vírgula menos a última, que termina em ; — é esse ponto e vírgula que avisa "acabou o comando".

✅ A tabela correta usa vírgula entre todas as colunas, o nome preco sem acento, e no INSERT cada produto tem seus 4 valores certos, terminando em ;.

2️⃣ Cadastrando os produtos

Agora vamos inserir os 5 produtos da loja usando INSERT INTO. Repare que aqui colocamos todas as linhas de uma vez, separadas por vírgula, e só a última termina em ;:

idnomeprecoquantidade
1Mouse5010
2Teclado1205
3Monitor9003
4Headset2008
5Webcam1506
SQL correto
INSERT INTO produtos (id, nome, preco, quantidade) VALUES (1, 'Mouse', 50, 10), (2, 'Teclado', 120, 5), (3, 'Monitor', 900, 3), (4, 'Headset', 200, 8), (5, 'Webcam', 150, 6);
⚠️ Textos (como o nome do produto) sempre entre aspas simples ' '. Números (como preço e quantidade) não levam aspas.

3️⃣ Consultando os produtos (SELECT)

Mostrar todos os produtos

SELECT * FROM produtos;

Resultado esperado:

idnomeprecoquantidade
1Mouse5010
2Teclado1205
3Monitor9003
4Headset2008
5Webcam1506

Mostrar apenas nome e preço

SELECT nome, preco FROM produtos;

Resultado esperado:

nomepreco
Mouse50
Teclado120
Monitor900
Headset200
Webcam150

WHERE — filtrando por preço

Quando queremos ver só os produtos acima de um certo preço, usamos WHERE. Aqui, produtos com preço maior que R$ 150:

SELECT * FROM produtos WHERE preco > 150;

Resultado esperado (só Monitor e Headset têm preço maior que 150):

idnomeprecoquantidade
3Monitor9003
4Headset2008

ORDER BY — ordenando por preço

Para organizar a lista do mais barato para o mais caro, usamos ORDER BY:

SELECT * FROM produtos ORDER BY preco ASC;

Resultado esperado:

idnomeprecoquantidade
1Mouse5010
2Teclado1205
5Webcam1506
4Headset2008
3Monitor9003

Use DESC no lugar de ASC para inverter, do mais caro para o mais barato.

4️⃣ Atualizando dados (UPDATE)

Imagine que o preço do Teclado mudou para R$ 135. Para atualizar um registro já existente, usamos UPDATE junto com WHERE — sem o WHERE, o comando atualizaria a coluna em todas as linhas da tabela!

UPDATE produtos SET preco = 135 WHERE nome = 'Teclado';

Resultado esperado (consultando novamente com SELECT * FROM produtos;):

idnomeprecoquantidade
1Mouse5010
2Teclado1355
3Monitor9003
4Headset2008
5Webcam1506

5️⃣ Removendo dados (DELETE)

Se a loja parou de vender a Webcam, removemos o registro com DELETE — também sempre com WHERE, para apagar só o produto certo:

DELETE FROM produtos WHERE nome = 'Webcam';

Resultado esperado (a Webcam sai da tabela):

idnomeprecoquantidade
1Mouse5010
2Teclado1355
3Monitor9003
4Headset2008
⚠️ Cuidado: tanto o UPDATE quanto o DELETE sem WHERE afetam a tabela inteira. É um dos erros mais perigosos em SQL — sempre confira a condição antes de rodar o comando.

✅ Checklist da atividade

  • Criei a tabela produtos com id, nome, preco e quantidade, usando vírgula entre todas as colunas.
  • Usei preco sem acento no nome da coluna.
  • Inseri os 5 produtos (Mouse, Teclado, Monitor, Headset, Webcam) com um único INSERT terminando em ;.
  • Consultei todos os produtos e depois só nome e preço.
  • Filtrei produtos com WHERE por preço.
  • Ordenei os produtos com ORDER BY.
  • Atualizei um preço com UPDATE ... WHERE.
  • Removi um produto com DELETE ... WHERE.
