📱 Ionic e Cordova — Primeiros Passos

Do zero ao seu primeiro aplicativo de celular rodando no navegador

⏱️ Duração estimada: 1 hora e 30 minutos

Índice

    Nível: Já sabe HTML, CSS e um pouco de JS
    Tempo: ~1h30
    Requisitos: Node.js, Cordova e Ionic já instalados

    1. Bem-vinda! Da Web para o Mobile

    Você já sabe montar uma página com HTML, deixar ela bonita com CSS e fazer coisas acontecerem com JavaScript. Isso é muito — a maioria das pessoas nunca chega nem perto disso. A partir de hoje, você vai usar exatamente esse conhecimento pra construir algo novo: um aplicativo de celular de verdade.

    Repare na diferença: um site precisa de um navegador aberto pra existir. Um aplicativo tem um ícone próprio na tela do celular, abre sozinho, e pode ficar guardando informações mesmo sem internet. Isso muda algumas coisas — mas a base continua sendo HTML, CSS e JavaScript, os mesmos três amigos de sempre.

    🎯 O que você vai construir

    Ao longo desta e das próximas atividades, você vai criar um aplicativo chamado Minhas Missões — uma lista de tarefas (ou o que você preferir: filmes, livros, ideias) que lembra do que foi digitado mesmo depois de fechar o app, e que no final vai rodar dentro de um celular Android simulado no computador.

    Hoje, especificamente, você vai: entender as duas ferramentas novas que tornam isso possível, criar seu primeiro projeto pelo terminal, e montar as primeiras peças visuais da tela. Vamos com calma — cada capítulo do menu ao lado é um pedacinho novo.

    2. O que é um Aplicativo Híbrido?

    Existem, basicamente, três formas de criar um aplicativo de celular:

    TipoComo é feitoExemplo
    NativoEscrito numa linguagem própria do sistema (Kotlin no Android, Swift no iPhone)Muitos jogos pesados
    WebÉ só um site que você acessa pelo navegador do celularUm site qualquer aberto no Chrome do celular
    HíbridoEscrito com HTML/CSS/JS, mas "empacotado" pra virar um app de verdade, com ícone e tudoÉ isso que você vai fazer hoje

    O caminho híbrido é ótimo pra quem já sabe desenvolver pra web (como você!) porque aproveita 100% do que você já aprendeu, sem precisar decorar uma linguagem nova do zero. Muitos aplicativos reais — de lojas, de delivery, de organização pessoal — são construídos assim.

    🚗 Pensa num carro flex

    Um carro "nativo" só roda com um tipo específico de combustível, feito sob medida pra ele. Um app híbrido é como um carro flex: o "motor" (o código HTML/CSS/JS) é o mesmo, mas ele consegue rodar tanto num Android quanto num iPhone, porque existe uma "tradução" no meio do caminho.

    3. Conhecendo o Ionic

    Ionic é uma biblioteca de componentes visuais prontos — botões, menus, cartões, listas, campos de texto — todos já desenhados com a cara de aplicativo de celular de verdade. Em vez de você desenhar um botão do zero com CSS (bordas, sombra, cor, tamanho de toque adequado pro dedo), o Ionic já entrega ele pronto, faltando só você preencher com o seu conteúdo.

    🪑 Móveis prontos, não madeira crua

    Imagine montar uma casa. Você poderia serrar cada tábua e construir cada móvel do zero (é possível, mas demorado). Ou poderia comprar móveis já prontos, no tamanho certo, e só posicionar eles onde quiser. O Ionic é a loja de móveis prontos — só que os "móveis" são pedaços de interface de aplicativo.

    Tecnicamente, os componentes do Ionic são feitos com uma tecnologia chamada Web Components — isso significa que eles funcionam como tags HTML normais, só que com super poderes. Você vai ver isso na prática já neste capítulo: uma tag como <ion-button> se comporta exatamente como um <button> comum, só que já vem toda estilizada.

    Um gostinho do que vem por aí

    Aqui está, só pra você ver, como fica um botão feito com Ionic (não precisa copiar nada ainda, isso vem nos próximos capítulos):

    html<ion-button color="success"> <ion-icon name="star"></ion-icon> Meu botão bonito </ion-button>

    Uma linha de HTML, e você já tem um botão verde, arredondado, com ícone, do jeito que apareceria num app de verdade. Sem escrever nenhum CSS.

    4. Conhecendo o Cordova

    Só ter componentes bonitos não basta — o navegador do computador não é um celular. É aqui que entra o Cordova: ele pega tudo o que você escreveu em HTML/CSS/JS e "embrulha" isso de um jeito que o sistema operacional do celular (Android ou iPhone) reconhece como um aplicativo de verdade, com ícone, permissão de instalar, e tudo mais.

    🚚 O caminhão de mudança

    Se o Ionic são os móveis prontos, o Cordova é o caminhão de mudança: ele pega a "casa" inteira que você construiu (seu HTML, CSS e JS) e leva ela pra dentro do celular, cuidando de toda a parte chata de tradução — como instalar, como abrir, como aparecer na tela de aplicativos.

    O Cordova também é o responsável por, no futuro, dar acesso a coisas que só um app de verdade consegue usar — como a câmera do celular, o GPS, os contatos, o giroscópio. Essas funções chamam-se plugins. Você não vai usar plugins nesta atividade, mas é bom saber que eles existem: é uma das razões pelas quais desenvolvedores escolhem apps híbridos em vez de sites comuns.

    5. Como Ionic e Cordova Trabalham Juntos

    Veja o caminho completo do seu código até aparecer na tela de um celular:

    Seu HTML + CSS + JS
    ↓
    Componentes visuais do Ionic
    ↓
    Cordova empacota tudo
    ↓
    📱 Roda no celular como um app de verdade

    Cada camada tem seu papel. Você escreve o código (camada 1), usa peças prontas pra ele parecer um app (camada 2), e o Cordova cuida de levar isso pro celular (camada 3). No final, o resultado é um app funcionando de verdade (camada 4). Vamos começar a construir essa pilha agora, de baixo pra cima, na prática.

    6. O Terminal — Seu Novo Melhor Amigo

    Diferente de um site, que você cria só clicando e salvando arquivos, projetos Cordova são criados e executados por comandos de texto, digitados numa janela chamada terminal (ou "linha de comando", ou "prompt"). Pode parecer estranho no início, mas é só um jeito de "conversar" diretamente com o computador, digitando instruções em vez de clicar em botões.

    💡 Não precisa decorar nada

    Os comandos que você vai usar aqui são sempre os mesmos, poucos e curtos. Depois de usar umas 3 vezes, eles ficam automáticos — é como decorar o caminho de casa pra escola: parece complicado só na primeira vez.

    Alguns comandos básicos que valem saber:

    ComandoO que faz
    cd nome-da-pasta"Entra" dentro de uma pasta (cd = "change directory", trocar de pasta)
    cd ..Volta uma pasta pra trás
    dir (Windows) ou ls (Mac/Linux)Lista o que existe dentro da pasta atual

    Você não precisa decorar isso agora — vamos usar só o essencial, e sempre explicando o que cada comando faz antes de digitar.

    7. Criando Seu Primeiro Projeto

    O computador já tem tudo instalado — Node.js, Cordova e Ionic — então você não precisa instalar nada, só usar. Abra o terminal na pasta onde quer guardar seus projetos, e digite o primeiro comando:

    $ cordova create meu-app com.escola.meuapp "Minhas Missões"

    Esse comando tem 3 partes, cada uma com um papel:

    1. meu-app — o nome da pasta que vai ser criada no seu computador;
    2. com.escola.meuapp — um "identificador único" do aplicativo. Todo app de celular precisa de um, parecido com um CPF: ninguém mais no mundo pode ter o mesmo. A convenção é escrever de trás pra frente (empresa.organização.nomedoapp);
    3. "Minhas Missões" — o nome que vai aparecer escrito embaixo do ícone, no celular.
    ⚠️ Esse comando demora um pouquinho a primeira vez (ele está baixando e organizando vários arquivos por trás dos panos). Não feche o terminal, só espere aparecer o cursor piscando de novo.

    8. Rodando o App pela Primeira Vez

    Com o projeto criado, entre na pasta dele e prepare a pré-visualização no navegador:

    $ cd meu-app $ cordova platform add browser $ cordova run browser → abrindo http://localhost:8000 no navegador...

    O primeiro comando entra na pasta. O segundo ensina o Cordova a rodar dentro de um navegador comum (é a forma mais rápida de testar, sem precisar de celular nenhum por enquanto). O terceiro efetivamente abre o app — uma aba nova deve aparecer sozinha, mostrando uma tela simples de boas-vindas do Cordova.

    🎉 Se você chegou até aqui e uma aba abriu com alguma coisa na tela, parabéns — você acabou de criar e rodar seu primeiro projeto de aplicativo de celular!

    9. Explorando a Pasta www/

    Abra a pasta meu-app no seu editor de código. Ela tem bastante coisa dentro, mas 99% não importa pra você agora — o Cordova usa isso por trás dos panos pra funcionar. O que importa é uma única pasta: www.

    o que importa, dentro de www/ meu-app/ └── www/ ├── index.html # a tela do seu app ├── css/ │ └── index.css # o estilo visual └── js/ └── index.js # a lógica — o que acontece quando você toca em algo

    É exatamente como um site comum: um arquivo HTML, uma pasta de CSS, uma pasta de JS. A diferença é só que, quando você roda cordova run, o Cordova pega esses arquivos e faz eles virarem um app de verdade.

    Abra o www/index.html. No <head>, você vai ver algumas linhas já preparadas que carregam a biblioteca do Ionic — é isso que faz tags como <ion-button> funcionarem. Não precisa mexer nelas, só saber que estão ali fazendo esse trabalho.

    10. Seu Primeiro Componente — o Cabeçalho

    Vamos trocar o conteúdo de dentro do <body> do index.html pelo primeiro componente de verdade: um cabeçalho fixo no topo, igual todo app de celular tem.

    Copie isto dentro do <body>
    www/index.html<ion-app> <ion-header> <ion-toolbar color="primary"> <ion-title>Minhas Missões</ion-title> </ion-toolbar> </ion-header> <ion-content class="ion-padding"> </ion-content> </ion-app>

    O que cada tag faz

    • <ion-app> — envolve o app inteiro, é tipo o <body> de um app Ionic;
    • <ion-header> — a área fixa do topo;
    • <ion-toolbar color="primary"> — a barra dentro do cabeçalho; color="primary" usa a cor principal do tema (o azul do Ionic);
    • <ion-title> — o texto que aparece na barra;
    • <ion-content class="ion-padding"> — a área rolável onde o resto do conteúdo vai entrar; ion-padding dá um respiro nas bordas.
    💾 Salve o arquivo agora e recarregue a aba do navegador (ou rode cordova run browser de novo). Deve aparecer uma barra azul no topo com "Minhas Missões" escrito. Sem uma linha de CSS, já parece um app de verdade.

    11. Adicionando um Cartão de Boas-vindas

    Agora vamos preencher o <ion-content> vazio com um cartão — um dos componentes mais usados em qualquer app, pra destacar um bloco de conteúdo.

    Copie dentro do <ion-content class="ion-padding">
    www/index.html<ion-card> <ion-card-header> <ion-card-title>Bem-vinda!</ion-card-title> </ion-card-header> <ion-card-content> Este é o meu primeiro aplicativo de celular, criado por mim! </ion-card-content> </ion-card>

    <ion-card> é o cartão inteiro; <ion-card-header> e <ion-card-title> formam o título dele; <ion-card-content> é onde vai o texto. Salve e recarregue: apareceu um retângulo branco com cantos arredondados e uma sombrinha sutil — mais uma vez, tudo isso vem pronto do Ionic.

    Brinque um pouco

    Antes de continuar, tente sozinha:

    • Duplicar o cartão inteiro e escrever um segundo, com outro texto;
    • Trocar o texto do <ion-title> por outro nome de app.

    12. Personalizando as Cores

    O Ionic vem com um conjunto de cores prontas, pensadas pra funcionar bem juntas. Você já usou color="primary" — aqui estão todas:

    NomeUso comum
    primarya cor principal do app (geralmente a marca)
    secondaryuma cor de apoio
    tertiaryoutra cor de apoio, pra variar
    successações positivas — verde, geralmente
    warningatenção — amarelo
    dangerações que apagam/cancelam algo — vermelho
    mediumelementos neutros, discretos
    darkfundo/texto escuro

    Troque color="primary" por color="danger" na sua <ion-toolbar> e recarregue — a barra inteira muda de cor sozinha. É assim que apps profissionais mantêm um visual consistente: usando um conjunto pequeno de cores combinadas, em vez de cores soltas em cada lugar.

    Se quiser ir além das cores prontas, dá pra criar a sua no CSS:

    www/css/index.cssion-toolbar { --background: #ff6b9d; /* rosa, por exemplo */ --color: #ffffff; }

    Aquele --background com dois traços é uma variável CSS interna do componente — é assim que se customiza uma cor quando as prontas não bastam.

    13. Modo Detetive — o Console do Navegador

    Vez ou outra, o app vai "quebrar" — a tela fica em branco, ou algo não aparece como esperado. Isso é completamente normal, acontece até com programadores profissionais, todos os dias. O segredo não é nunca errar — é saber onde procurar a pista.

    🔍 Como investigar um erro

    1. Aperte F12 no navegador (ou clique com o botão direito na página → Inspecionar);
    2. Clique na aba Console;
    3. Se algo deu errado, aparece uma linha em vermelho — geralmente com o nome do arquivo e o número da linha do problema;
    4. Leia como uma pista de investigação: quase sempre a mensagem diz exatamente o que está errado.

    Vamos provocar um erro de propósito, só pra você reconhecer como ele aparece. No seu index.html, apague de propósito o > do fim de uma tag, por exemplo troque <ion-title> por <ion-title (sem fechar). Salve, recarregue, e olhe o Console.

    Uncaught SyntaxError: Unexpected token ...

    Mensagens assim indicam que o navegador não conseguiu "entender" seu código em algum ponto. Desfaça o erro (Ctrl+Z) e confirme que a mensagem some.

    Você vai usar esse Console em toda atividade daqui pra frente — vale o hábito de deixar o F12 aberto sempre que estiver codando.

    14. Como Trabalhar Bem Durante a Aula

    Programar em blocos longos de aula pede alguns hábitos que fazem toda diferença:

    ⏱️ A técnica 50/10

    A cada uns 50 minutos codando, vale 10 minutos de pausa longe da tela — esticar as pernas, beber água, olhar pra longe. Até programador profissional trabalha assim; o cérebro absorve melhor o que aprendeu quando descansa entre os blocos.

    💾 Ciclo curto de salvar e testar

    Não escreva 30 linhas de código antes de testar pela primeira vez. A cada 3-5 linhas novas, salve (Ctrl+S) e recarregue o app. Assim, se algo quebrar, você sabe exatamente qual foi a última coisa que mudou — muito mais fácil de consertar do que procurar um erro em meio a 30 linhas.

    🕵️ Erros são pistas, não fracasso

    Toda mensagem vermelha no Console é uma dica, não um "você fez errado". Encare como investigar um mistério: qual foi a última mudança? O que a mensagem está dizendo? Onde exatamente (arquivo e linha) ela aponta?
