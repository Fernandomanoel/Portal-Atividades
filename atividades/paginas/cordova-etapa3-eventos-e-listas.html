🎯 O que vamos fazer

Sua tela já está pronta desde a Etapa 2: campo de texto, botão, lista vazia. Hoje, tudo isso ganha vida. Vamos escrever o código que faz o app escutar quando você clica no botão, pegar o que foi digitado, e desenhar isso na tela como um item novo da lista — tudo isso é JavaScript puro, o mesmo que você já usa em páginas web comuns.

👂 O que é um "evento"

Um evento é qualquer coisa que acontece na tela: um clique, uma tecla apertada, um campo preenchido. Em JavaScript, a gente "escuta" um evento com addEventListener — é como dizer pro computador: "fica de olho nesse botão, e quando alguém clicar nele, roda esse pedaço de código".

Abra o www/js/index.js (crie o arquivo se ele ainda não existir, e confira que ele está sendo carregado no final do <body> do seu index.html com <script src="js/index.js"></script>).

🧩 Passo a passo do código

  1. Encontrar os elementos da tela. Toda a lógica começa "pegando" os elementos pelo id que você deu a eles na Etapa 2.
    www/js/index.jsconst campoMissao = document.getElementById('campo-missao'); const botaoAdicionar = document.getElementById('btn-adicionar'); const listaNaTela = document.getElementById('lista-missoes');

    Se algum id aqui estiver escrito diferente do que está no HTML (por exemplo campoMissao vs campo-missão com acento), o JavaScript não vai achar o elemento — é o erro mais comum nesta etapa, e o Console (F12) vai te ajudar a descobrir.

  2. Criar uma "caixa" para guardar as missões. Um array (lista) vazio, que vai crescer conforme você adiciona itens.
    www/js/index.jslet missoes = [];
  3. Escutar o clique do botão.
    www/js/index.jsbotaoAdicionar.addEventListener('click', () => { const texto = campoMissao.value; // o que está escrito no campo if (texto !== "") { // só adiciona se não estiver vazio missoes.push(texto); // adiciona no fim da lista desenharLista(); // atualiza o que aparece na tela campoMissao.value = ""; // limpa o campo pra próxima missão } });

    Repare: o clique só guarda o texto no array missoes e chama uma função chamada desenharLista(). Ela ainda não existe — vamos criar ela agora.

  4. Desenhar a lista na tela. Essa é a parte mais importante: toda vez que algo muda no array, apagamos a lista da tela e desenhamos ela de novo do zero, item por item.
    www/js/index.jsfunction desenharLista() { listaNaTela.innerHTML = ""; // apaga tudo que estava desenhado antes missoes.forEach((missao, indice) => { listaNaTela.innerHTML += ` <ion-item> <ion-label>${missao}</ion-label> </ion-item> `; }); }

    forEach passa por cada item do array, um de cada vez. missoes.forEach((missao, indice) => {...}) quer dizer: "pra cada missao dentro do array, na posição indice, faça isto". As crases ` ` criam uma template literal — um jeito de escrever HTML como texto, colando o valor de uma variável no meio com ${missao}.

💾 Teste agora! Salve, rode cordova run browser, digite uma missão no campo e clique em "Adicionar Missão". Ela deve aparecer na lista. Digite mais uma. E mais outra. Se funcionou, você acabou de programar sua primeira interação de verdade num app.

🗑️ Adicionando um botão de excluir

Uma lista de missões que nunca esvazia não é muito útil. Vamos adicionar um botão de lixeira em cada item, que remove aquela missão específica.

Atualize a função desenharLista()

www/js/index.jsfunction desenharLista() { listaNaTela.innerHTML = ""; missoes.forEach((missao, indice) => { listaNaTela.innerHTML += ` <ion-item> <ion-label>${missao}</ion-label> <ion-button slot="end" color="danger" fill="clear" onclick="excluirMissao(${indice})"> <ion-icon name="trash" slot="icon-only"></ion-icon> </ion-button> </ion-item> `; }); } function excluirMissao(indice) { missoes.splice(indice, 1); // remove 1 item, na posição "indice" desenharLista(); // redesenha a lista sem ele }

slot="end" coloca o botão na ponta direita do item. fill="clear" deixa o botão "transparente", só com o ícone visível, sem fundo colorido. splice(indice, 1) é um comando de array que remove exatamente 1 item, começando na posição indice — é assim que a missão certa desaparece da lista.

🕵️ Modo detetive: erros de propósito

Vamos provocar 3 erros comuns de propósito, pra você reconhecer eles quando aparecerem sozinhos (e vão aparecer, isso é normal).

Erro 1 — Esqueceu de fechar uma aspa

const texto = campoMissao.value
// faltou o ; no fim — às vezes o JS perdoa, às vezes não

Se você apagar um ;, o JS às vezes ainda funciona (ele é tolerante), mas se apagar uma aspa ' ou " no meio de um texto, o Console mostra algo como Uncaught SyntaxError: missing ) after argument list. Tente apagar de propósito uma aspa do addEventListener('click', ...), salve, veja o erro no F12, e depois desfaça (Ctrl+Z).

Erro 2 — Nome de variável escrito diferente

const campoMisao = document.getElementById('campo-missao'); // ... campoMissao.value // "campoMissao" com dois esses — não existe!

O Console mostra Uncaught ReferenceError: campoMissao is not defined — quer dizer que em algum lugar você usou um nome de variável que nunca foi criado exatamente daquele jeito. JavaScript é exigente com maiúsculas, minúsculas e cada letrinha.

Erro 3 — id do HTML diferente do id usado no JS

<ion-button id="botao-add">... // mas no JS: document.getElementById('btn-adicionar')

Aqui não aparece um erro vermelho — o app simplesmente não faz nada quando você clica. Esse é o mais chato de descobrir, porque não tem mensagem de ajuda. A dica de detetive aqui é: sempre que um clique "não faz nada", confira se o id no HTML é exatamente igual ao id usado no getElementById do JavaScript.

✅ Checklist da Etapa 3

  • O botão "Adicionar Missão" realmente adiciona o texto digitado na lista;
  • O campo de texto limpa sozinho depois de adicionar;
  • Cada item da lista tem um botão de lixeira que remove só aquele item;
  • Testei os 3 erros de propósito e reconheci as mensagens no Console (F12);
  • Se tento adicionar com o campo vazio, nada acontece (o if está funcionando).
Um problema pra pensar até a próxima aula: feche a aba do navegador e abra de novo. O que aconteceu com a sua lista de missões? Ela sumiu, certo? Isso é porque o array missoes vive só na memória temporária do navegador. Na Etapa 4 a gente resolve isso de vez, com uma coisa chamada localStorage — a memória permanente do app.
